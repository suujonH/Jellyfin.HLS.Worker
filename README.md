# Jellyfin HLS Worker

为 Jellyfin 预编码 HLS 的桌面程序。它向服务器领取任务，用 ffmpeg 把视频编码成多个档位的 HLS，上传到上传方案中的目录（S3、SFTP 或本机目录），再报告给服务器；服务器校验后发布，播放时直接交付这些成果。

它还能把本机文件**添加到媒体库**：原片按上传方案上传到各个目录，媒体库目录中的 `.strm`、TrueCache 条目、字幕、图片和 nfo **经服务器写入**，Worker 不直接访问媒体库目录。添加时可以立即编码该媒体库的部分或全部档位。

需要带 HLS 任务中心的 Jellyfin 服务器（**协议版本 3**；版本不同时直接报错），以及一个管理员 API Key。

## 包内容

发布包依赖框架，需要先安装 **.NET 10 运行时**和 **ASP.NET Core 10 运行时**（TrueCache 工具运行服务器的代码，需要后者）。提供 `win-x64`、`linux-x64`、`linux-arm64` 三种。

- Windows：从 [.NET 10 下载页](https://dotnet.microsoft.com/download/dotnet/10.0) 安装「.NET Runtime」和「ASP.NET Core Runtime」。
- Linux：安装发行版或 Microsoft 软件源中的 `aspnetcore-runtime-10.0` 包，它会同时装上 .NET 运行时。

| 文件 | 说明 |
| --- | --- |
| `jellyfin-hls-worker-gui` | 桌面程序 |
| `truecache/` | `Jellyfin.TrueCache.Tool`，原片不放进媒体库时生成 TrueCache 条目 |
| `ffmpeg`、`ffprobe`（Windows 为 `.exe`） | [jellyfin-ffmpeg](https://github.com/jellyfin/jellyfin-ffmpeg) 8.1.3-1 的 portable 版，GPL 许可，源码见 [v8.1.3-1](https://github.com/jellyfin/jellyfin-ffmpeg/tree/v8.1.3-1) |

- **ffmpeg、ffprobe**：程序目录下有 `ffmpeg`、`ffprobe`（Windows 为 `.exe`）时使用它们，否则从 PATH 查找。发布包自带 jellyfin-ffmpeg：HDR 色调映射需要的 `zscale`、GPU 流水线需要的 CUDA 滤镜和各硬件编码器它都带有，所有 Worker 也因此用同一版本探测。要改用 PATH 中的 ffmpeg，删除包内这两个文件。
- **TrueCache 工具**：使用包内 `truecache/` 中的工具，包内没有时从 PATH 查找 `Jellyfin.TrueCache.Tool`。它运行的是服务器自己的探测和提取代码，在 Linux 上需要 libicu（`libicu` 或 `icu-libs` 包）。工具与 Worker 一起发布，硬件加速按 Worker 的「编码器」「硬件设备」设置，不使用服务器的设置；Worker 需要支持 `--hwaccel` 的工具。工具用硬件失败时，Worker 改用 CPU 重试一次。
- Windows 打出的 `.tar.gz` 不带可执行权限。运行前先执行：
  ```sh
  chmod +x jellyfin-hls-worker-gui truecache/Jellyfin.TrueCache.Tool ffmpeg ffprobe
  ```

## 数据目录

所有数据在一个目录中：

- Windows：`%AppData%\Jellyfin.HLS.Worker\`
- Linux：`~/.config/Jellyfin.HLS.Worker/`
- 启动时加 `--data <目录>` 可以改用别的目录。

| 文件 | 说明 |
| --- | --- |
| `sqlite.db` | 配置、添加过的媒体、上传记录 |
| `work/` | 默认的临时文件目录：输入缓存、任务目录、添加视频的操作目录（`operations/`，见「添加媒体」），以及没有申告 HLS 目录时本机保存的 HLS（`hls/`，不会自动清理） |

- **从旧版本升级**：`sqlite.db` 中还没有配置、而数据目录中有旧版的 `worker.json` 时，启动时导入一次，原文件保留。
  - S3、SFTP 连接照搬；`Local` 连接变为「Worker目录」；`ServerRoot`、`DeclareOnly` 不再使用。
  - 旧的 HLS 根变为上传方案「导入的方案」中的一行申告的 HLS 目录；根带路径时，新建一个以该路径为根的远程目录。
  - 旧的媒体库默认去向不导入，需要在「媒体库配置」中重新选择。
  - 旧工作目录中 `worker.db` 记录的媒体一并导入。
- API Key 也可以由环境变量 `JELLYFIN_HLS_API_KEY` 提供，优先于设置。
- 配置中有管理员 API Key 和各远程目录的凭据，请只让自己可读数据目录。

## 运行

- **开始领取任务**：打开对话框，列出「预编码配置」中启用、且还有档位开着的媒体库，可以逐个为它们选择 HLS 方案（默认为媒体库配置中的方案）。没有可用 HLS 方案的媒体库会列出来确认，它们的任务被跳过，留给别的 Worker。
- **停止**：进行中的任务被中止，由服务器重新安排。
- 每次开始时清空「本机找不到原片」的例外列表，见下文「worker-local」。
- 运行中保存的设置，在停止后重新开始时生效。

## 添加媒体

点「添加文件…」「添加文件夹…」（都可以多选），或把文件拖到这一页，在对话框中选择后点「加入列表」：

- **媒体库**；媒体库有多个目录时还要选择**写入目录**（默认为媒体库配置中选的目录）。
- **源文件方案**和 **HLS 方案**。报给服务器的位置就是方案中勾选「申告此目录」的那一行；需要不同的申告位置时，克隆方案后改勾选。
- **预编码**：勾选立即编码的档位，可选的是服务器上该媒体库的档位减去「预编码配置」中关闭的档位。媒体库不在服务器的预编码列表中、档位全部关闭、或 HLS 方案没有 HLS 目录时不可选。

对话框中没有手动改过的选项，切换媒体库时跟随该媒体库的默认值；「预编码」的档位总是重置为媒体库的默认值。这些选择不写入设置。

列表中的每一项是一批文件。点「全部开始」依次执行；执行中加入的排在后面自动执行，没有执行时加入的等待下一次「全部开始」。进行中的一项可以「取消」，等待或结束的一项可以「移除」；「全部取消」取消进行中的一项和所有等待的项。结束的项（完成、失败、已取消）留在列表中，用「清除已完成」清除；再点「全部开始」时（执行中也可以点），失败或取消的项重新排队，从头执行这一项（其中已成功的文件也会再添加一次）；完成的项保持不变，包括有部分文件失败的项。重新执行使用当前保存的配置连接服务器，但媒体库、方案和档位仍是加入列表时选择的；如果其中用到的目录已在「远程目录」中删除，这一项不执行，直接标为「已取消」并注明原因，以后也不能再开始（需要重新添加），队列继续执行后面的项。执行期间 Worker 不领取新任务。

执行中，每个文件单独显示状态和当前步骤：计算校验值、准备（占用、续传与清理）、生成 TrueCache 条目、上传到某目录、写入媒体库、写入 .strm、申请编码、编码视频/音频、提取字幕、生成预览图、上传 HLS。有进度的步骤显示进度条和百分比，上传与校验显示已传大小和速度，编码显示已编码的媒体时长和倍速；右下角显示本步骤已用时间和剩余时间预估（进度达到 1% 且已用 3 秒后才估算）。多个文件的一项（例如文件夹）加入列表后即可点左侧的 ▸ 展开查看每个文件（开始执行时按当时文件夹中的文件重新列出），折叠时只显示正在处理的文件。编码期间已编码的 HLS 在后台上传；全部编码完成后若还有没传完的文件，显示「上传 HLS」及已传文件数。完成但未随添加编码的文件会注明原因（例如档位已存在）。

添加时：

- 文件夹连同文件夹名添加，目录结构为「文件夹名/其中的相对路径」。
- 原片依次上传到源文件方案的每个目录。
- 字幕、图片、nfo 等其他文件只经服务器写进媒体库目录，放在对应视频旁边，不上传到源文件目录。
- 两个文件会得到同一个名字时，在写入任何东西之前拒绝。
- 一批结束后，Worker 请服务器扫描该媒体库。
- **入库最后写**：视频的 .strm（连同 TrueCache 条目）或媒体库中的视频文件在原片上传、编码和 HLS 上传都完成之后才写入，服务器扫描时不会收录没有完成的视频。随添加编码失败的视频算作失败，不写入媒体库；档位已存在或已有任务在处理时只注明原因，照常写入。
- **占用**：每个视频开始时在服务器媒体库目录中、入库文件旁边的 `__working__/<入库文件名>` 写入本次操作的 id（服务器扫描时忽略这个目录），每 30 秒检查一次，写入媒体库前再检查一次。被别的 Worker 或别的添加接管（标记不再是自己的 id）时，本机跳过这个文件（显示「另一个任务接管了这个文件，本机已跳过。」），不删除任何远端文件，只删除本机的操作目录。成功后删除标记；失败或取消时保留。
- **续传**：失败或取消后再次添加同一文件（同一本地路径、大小和校验值），且标记中仍是本机上次的操作，就继续上次的操作：上次已上传且仍在目标上的原片和 HLS 不再上传，已编码完整的档位不再编码（服务器保留该编码任务的计划和目录 1 天）。
- **清理**：不能续传时，先删除本机上次添加同一入库文件留下、服务器没有收集的文件：HLS 总是删除；原片只在标记中正是那次操作、且这个路径没有被另一次成功的添加使用时删除；经服务器写进媒体库的文件不删除。删除失败只记警告。
- 本机的条目和编码产物放在 `work/operations/<操作 id>/`，成功、被接管或被清理时删除，失败或取消时保留以便续传。Worker 异常退出时，进行中的操作在下次启动时记为「已取消」。
- **本地数据库**：Worker 记下添加过的媒体。之后领到同一个文件的任务时，直接读本地文件，不再下载。所以添加后不要移动或修改本地文件，否则 Worker 会改为下载。

## 设置

左侧选择分类，底部「保存」把全部设置写入 `sqlite.db`。

### 全局设置

| 设置 | 默认值 | 说明 |
| --- | --- | --- |
| 服务器地址 | `http://localhost:8096` | 经反向代理时带上路径前缀 |
| API Key | — | 管理员在控制台「API 密钥」中创建 |
| Worker 名称 | 机器名 | 显示在服务器上 |
| Worker Id | 空 | 服务器以它区分 Worker。留空时第一次连接服务器时自动申请；也可以点「申请」，或手填一个 uuid，由服务器以它登记。重新申请会使之前用旧 Id 添加的 worker-local 媒体不再下发给本机 |
| 临时文件目录 | 数据目录下的 `work` | 相对路径相对于数据目录 |
| 编码器 | `libx264` | 可选 `h264_nvenc`、`h264_qsv`、`h264_amf`、`h264_vaapi`；也决定 TrueCache 工具生成 trickplay 时用哪种硬件解码。`h264_nvenc` 对 BT.709 的 SDR 源在 GPU 上解码、反交错和缩放（HDR、旋转、BT.601 和全范围的源仍在 CPU 上处理），GPU 失败时自动改用 CPU 重新编码 |
| 硬件设备 | — | VAAPI 填渲染节点（如 `/dev/dri/renderD128`，必填），NVENC 填 GPU 序号；TrueCache 工具使用同一个设备 |
| 线程数 | `0` | ffmpeg 的线程数，0 由 ffmpeg 决定 |
| 同时编码 | `1` | 同时下载输入、识别和编码的任务数 |
| 同时上传 | `1` | 同时上传的渲染组数（视频、音频、字幕各算一组）；编完的任务等待上传时，下一个任务可以开始编码。保存后立即生效 |
| 同时上传文件 | `4` | 整个 Worker 同时写入的 HLS 文件数，所有任务和远程目录共用；S3 大文件的分段并发另算。保存后立即生效 |
| 领取间隔（秒） | `10` | 没有领到任务时，两次领取之间的秒数 |
| 请求超时（秒） | `30` | 下载以外请求的超时秒数 |
| 输入缓存（GiB） | `20` | 0 表示任务完成后立即删除输入 |
| 保留失败任务的工作目录 | 否 | 便于排查 |

### 远程目录

「新建 ▾」时选择类型，**类型建好后不能修改**，要换类型就删除后新建。右键列表可以「克隆」「删除」。删除后，上传方案中用到它的行变为未选择目录（红字提示），需要重新选择或删除这一行。

| 类型 | 用途 | 字段 |
| --- | --- | --- |
| S3 | S3 兼容的桶 | Endpoint、Region（默认 `us-east-1`）、Bucket（服务器所知的桶名）、目录（桶中的目录，可留空）、Access Key、Secret Key、同时连接 |
| SFTP | SSH 服务器上的目录 | 主机、端口（默认 22）、主机密钥指纹、用户、密码或私钥文件（可带口令）、远端根目录 |
| 服务器目录 | 只有服务器能访问的目录 | 服务器上的绝对路径，例如 `/srv/media` 或 `D:\Media` |
| Worker目录 | 本机目录，例如挂载的共享 | 本机目录 |

- **服务器目录**只能用于申告：Worker 不能写入它，也不能测试它（测试结果显示「—」）。
- **SFTP** 勾选「申告此目录」时，远端路径就是申告给服务器的路径，适用于 SFTP 连的就是服务器的情况。否则不勾选它，另加一行服务器目录申告。
- **S3 的目录**：这个远程目录只用桶中的这个目录。目录为 `jellyfin/hls`、媒体库前缀为 `movies` 时，申告的根是 `s3://桶/jellyfin/hls/movies`。
- 方案中的行不再带路径：同一个桶或主机的不同目录，分别建成不同的远程目录（可以「克隆」后改目录）。
- **同时连接**：S3 中大于 64 MiB 的文件分段上传，这是同时上传的分段数，为 1、2、5、10、20、50 或 100。
  - 分段因网络、超时或服务端错误失败时，只重传这一段，分别在 2、4、8、16、32 秒后重试。仍然失败时整个上传撤销，不能断点续传。
  - 分段为 64 MiB；超过 10,000 段时自动加大到所需的整数 MiB，符合 AWS S3、Cloudflare R2 和 Backblaze B2 的要求。
- **主机密钥指纹**：SHA-256 指纹，格式与 `ssh-keygen -lf` 的输出相同。留空时接受任何密钥，并在日志中记下。
- **测试** 测试当前目录，**测试全部** 同时测试所有目录：在目录中写删一个测试对象。结果显示在列表右侧（✓ 成功、✗ 失败、— 无法测试），鼠标悬停看原因。测试不需要先保存。

### 上传方案

一个方案由「HLS 保存路径」和「源文件保存路径」两组行组成。方案名在右侧直接编辑（1–64 个字符），可以与其他方案重名，内部按 Id 引用。右键列表可以「克隆」「删除」：克隆得到名为「原名 副本」（重名时「副本2」「副本3」……）的相同方案；删除方案后，用它作默认方案的媒体库变为「(无)」。

每一行是一个**目录**（远程目录，源文件组还可以选「Jellyfin 媒体库」）和一个 **「申告此目录」** 勾选框：

- 文件依次上传到每一行的目录（服务器目录除外），媒体库的前缀接在目录后面。
- 勾选「申告此目录」的行报给服务器，其余为备份。**每组最多勾选一个**，勾选一行时同组其他行自动取消。
- 一个都不勾选时：
  - HLS 照常上传到各行，另外保存在本机临时文件目录下的 `hls/<前缀>`，以 `worker-local://<Worker Id>/<该目录>` 申告。服务器直接采用 Worker 报告的文件发布，但读不到这些文件，**播放会失败**，只适合在本机保存成果。
  - 源文件申告为本机文件（见下表最后一行）。

规则（违反时该行显示红字；仍可保存，但状态栏提示配置还不能使用，不能开始领取任务或添加媒体）：

- 每一行都要选择目录。
- **服务器目录**不能上传，所在行必须勾选「申告此目录」。HLS 申告服务器目录时，还需要另一行实际上传 HLS 的目录（例如连到服务器的 SFTP）。
- HLS 行不能选「Jellyfin 媒体库」。
- 源文件行可以选 **「Jellyfin 媒体库」**：原片经服务器直接放进媒体库目录。它总是申告（勾选框锁定），同组其他行不能再勾选，且只能有一行。

旧版本的方案在读取时自动升级：行中带路径的，新建一个以「原目录 + 路径」为根的远程目录（名为「原名/路径」）；每组只保留第一个申告的行；「上传到 A、申告到服务器目录 B」变为两行，A 上传、B 申告；申告到其他目录的设置不再保留。

源文件申告决定媒体库中写什么：

| 申告 | 媒体库目录中 |
| --- | --- |
| Jellyfin 媒体库 | 原片本身 |
| 服务器目录、SFTP | 不写 `.strm`：原片本身就是媒体库文件，所以申告的位置必须在所选媒体库目录之内，否则添加时报错 |
| S3 | `.strm` 指向 `s3://桶/…`，旁边 `__true_cache__/` 中写 TrueCache 条目 |
| Worker目录 | `.strm` 指向 `worker-local://<Worker Id>/<Worker目录中的副本>` |
| 没有勾选申告的行，或源文件方案为「(无)」 | `.strm` 指向 `worker-local://<Worker Id>/<添加时的本机文件>` |

- 写 `.strm` 时先就位条目，最后写 `.strm`，所以扫描读到 `.strm` 时条目已经完整。
- 申告为 S3 且服务器还没有这个桶的访问权限时，Worker 用自己的凭据为服务器建一条。

### 媒体库配置

「刷新」从服务器读取媒体库（启动时，若已填服务器地址和 API Key，也自动刷新一次）。服务器上已没有的媒体库显示为灰底、删除线。

- **默认方案**：添加媒体和开始领取任务时的默认方案，「(无)」表示没有。
- **写入目录**：媒体库有多个目录时出现，添加对话框的默认写入目录。
- **前缀名**：接在方案中各目录后面，例如 `movies`。「源文件上传时使用前缀」「HLS 上传时使用前缀」分别控制两组是否使用。
- **预编码**：添加时默认立即编码的档位（服务器的档位减去「预编码配置」中关闭的档位）。该媒体库不在服务器的预编码列表中、或档位全部关闭时不可选；勾选过又被关闭的档位，重新打开后仍是勾选的。

### 预编码配置

「刷新」从服务器读取预编码的媒体库及其档位。新发现的媒体库默认启用；服务器已不再预编码的显示为灰底、删除线。只有勾选「启用」的媒体库出现在「开始领取任务」中。

右侧可以逐个关闭档位（服务器以后新增的档位默认打开）。关闭的档位本机不编码：添加媒体时不可选；领取任务时，只含关闭档位的任务留给其他 Worker，其余任务中关闭的档位交还服务器，由服务器另建任务给其他 Worker。档位全部关闭的媒体库不领取任务。需要 2026-10-24 之后的服务器（`ExcludedQualities`），旧服务器会忽略这个设置。

## 上传记录

按文件分组：每个添加的文件（或领取的编码任务）一行，显示时间、类型（添加、编码任务）、状态（进行中、完成、失败、已取消、已被接管，清理后加注「已清理」；悬停看原因）、文件、目标、文件数（含失败数）和已上传大小。点左侧的 ▸ 展开查看其中每个上传的文件（HLS 每个分片一条）：类型（源文件、HLS、媒体库文件、.strm、TrueCache）和结果。失败的操作中，失败的那条为「失败」，其余为「已取消」；被后来的添加删除的为「已清理」；进行中的操作中已传完的为「已上传」。旧版本的记录没有分组，各占一行。显示最近 1000 项，切换到这一页时刷新。

## worker-local

原片没有服务器可读的位置时，`.strm` 写 `worker-local://<Worker Id>/<本机路径>`：

- 服务器不能播放、下载或转码这个原片，有已发布的 HLS 时只提供 HLS。
- 它的任务只下发给这台 Worker。
- 领到任务时本机找不到这个文件（或大小不同），Worker 把任务交还服务器（不计失败），并在本次运行中不再领取它；下次「开始领取任务」时重新尝试。

## 安全

- 生成 TrueCache 条目时，Worker 以 `--api-key` 参数把 API Key 传给 TrueCache 工具。工具运行期间，**本机其他用户可以在进程列表中看到它**。在多人共用的机器上添加媒体时请注意这一点。

## 从源码构建

需要 .NET 10 SDK。

```sh
dotnet build -c Release
dotnet test -c Release
```

S3 测试只在设置环境变量 `HLS_WORKER_TEST_S3`（服务地址，如 `http://localhost:8333`）以及 `HLS_WORKER_TEST_S3_KEY`、`HLS_WORKER_TEST_S3_SECRET` 时运行。

打发布包需要 jellyfin 仓库的源码，TrueCache 工具从其中的 `src/Jellyfin.TrueCache.Tool` 发布：

```sh
sh scripts/publish.sh ../jellyfin [win-x64 linux-x64 linux-arm64]
```

```powershell
./scripts/publish.ps1 -Jellyfin ../jellyfin [-Runtime win-x64,linux-x64,linux-arm64]
```

包和压缩包输出到 `artifacts/`。脚本从 jellyfin-ffmpeg 的 Release 下载各平台的 portable 版（需要联网；`publish.sh` 还需要 `curl`、`unzip`、`xz`），核对 SHA-256 后放进包里，下载的文件缓存在 `artifacts/jellyfin-ffmpeg/`。升级 jellyfin-ffmpeg 时，两个脚本中的版本和 SHA-256 一起修改。

### CI

GitHub Actions（`.github/workflows/build.yml`）在推送到 `main` 和 PR 时运行测试并打包，三个平台的包可以在运行页面的 Artifacts 中下载。TrueCache 工具从 workflow 中 `JELLYFIN_REF` 指定的服务器版本发布，升级配套的服务器时一并修改。

推送 `v*` 标签时，先确认标签与 `Directory.Build.props` 中的 `Version` 一致，再把 `.zip` 和 `.tar.gz` 附加到同名 Release；Release 不存在时创建为预发布。
